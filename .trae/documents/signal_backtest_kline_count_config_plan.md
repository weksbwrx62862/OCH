# 信号回测K线数量调整功能实现计划

## 项目概述
当前信号预览功能中的K线加载数量硬编码为500，需要修改为用户可配置的选项，以提供更灵活的回测体验。

## 任务分解

### [ ] 任务1：添加K线数量配置UI组件
- **优先级**: P0
- **依赖**: 无
- **描述**:
  - 在信号预览对话框中添加K线数量选择控件
  - 提供合理的默认值和可选范围
  - 确保UI与现有设计风格一致
- **成功标准**:
  - 用户可以在信号预览对话框中看到并调整K线数量
  - 控件样式与现有UI保持一致
- **测试要求**:
  - `programmatic` TR-1.1: 控件能够正常显示并接收用户输入
  - `human-judgement` TR-1.2: 控件位置合理，操作直观

### [ ] 任务2：修改API调用逻辑
- **优先级**: P0
- **依赖**: 任务1
- **描述**:
  - 将硬编码的K线数量(500)替换为用户配置的值
  - 确保所有相关API调用都使用相同的K线数量参数
  - 处理边界情况和默认值
- **成功标准**:
  - API调用中使用用户配置的K线数量
  - 所有相关API调用保持一致
- **测试要求**:
  - `programmatic` TR-2.1: API请求中包含正确的count参数
  - `programmatic` TR-2.2: 不同K线数量设置下API调用正常

### [ ] 任务3：更新状态管理和数据流
- **优先级**: P1
- **依赖**: 任务1, 任务2
- **描述**:
  - 添加K线数量状态管理
  - 确保状态在组件间正确传递
  - 处理默认值和用户输入验证
- **成功标准**:
  - K线数量状态正确管理
  - 状态变化能够触发重新获取数据
- **测试要求**:
  - `programmatic` TR-3.1: 状态更新正确触发API调用
  - `programmatic` TR-3.2: 默认值设置合理

### [ ] 任务4：测试和验证
- **优先级**: P1
- **依赖**: 任务1, 任务2, 任务3
- **描述**:
  - 测试不同K线数量设置下的功能
  - 验证UI交互和数据加载
  - 确保边界情况处理正确
- **成功标准**:
  - 所有功能正常工作
  - 不同K线数量设置下性能良好
- **测试要求**:
  - `programmatic` TR-4.1: 不同K线数量设置下信号预览正常
  - `human-judgement` TR-4.2: 整体用户体验流畅

## 技术实现要点
1. 在SignalManager.tsx中添加K线数量状态和UI控件
2. 修改所有相关API调用，使用动态K线数量参数
3. 确保状态管理和数据流的一致性
4. 测试不同K线数量设置的性能和正确性

## 预期结果
用户可以在信号预览对话框中自由调整K线数量，从当前的固定500根调整为可选值，提高回测的灵活性和适用性。
