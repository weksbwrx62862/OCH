# 多 Agent 协作系统流程优化分析报告

**分析日期**：2026-03-23
**审查范围**：调度中心 → 规划部 → 审核部 → 执行部 完整链路

---

## 一、流程现状总览

```
用户 → 调度中心 → [流程卡审批] → 规划部 → 审核部 → 执行部 → 调度中心 → 用户
                         ↑                    ↑
                      等待批准              最多3轮
```

**关键配置**：
- 断路器：3次循环、30分钟超时
- 规划部：起草方案 → 审核部审议 → 执行部执行
- 审核部：最多3轮，第3轮强制批准

---

## 二、问题识别与优化建议

### 问题 1：双重审批导致流程冗长

**现状**：
- 调度中心需要等待用户批准"流程卡"（审批1）
- 规划部方案需要审核部审议（审批2）
- 两次审批串联，增加等待时间

**影响**：
- 简单任务需要等待2次审批
- 用户可能对重复审批感到烦躁

**优化建议**：
```
方案A：简化审批流
- 简单任务：调度中心直接派执行部门，跳过规划部
- 复杂任务：只保留审核部审批，跳过流程卡审批

方案B：并行审批
- 流程卡审批和规划部方案起草并行进行
- 用户批准流程卡时，规划部同时准备方案

推荐：方案A
- 在 MEMORY.md 中明确定义"简单任务"标准
- 简单任务链路：调度中心 → 执行部门 → 用户
```

### 问题 2：规划部成为潜在瓶颈

**现状**：
- 所有复杂任务都经过规划部
- 规划部需要设计完整方案后才能转审核部

**影响**：
- 规划部任务堆积
- 用户等待时间增加

**优化建议**：
```
方案A：引入"预规划"机制
- 调度中心识别到复杂任务后，立即分派给规划部
- 规划部快速产出"初步方案"后立即转审核部
- 详细方案在执行过程中补充

方案B：分级规划
- L1规划（快速）：调度中心判断任务类型，直接分派
- L2规划（完整）：规划部详细拆解执行步骤

推荐：方案B
- 在 AGENTS.md 中增加"快速规划"模式
- 简单任务≤3步时，跳过规划部
```

### 问题 3：审核部"最多3轮"与"第3轮强制批准"存在逻辑冲突

**现状**：
- review_dept/SOUL.md 第114行："最多 3 轮，第 3 轮强制批准"
- review_dept/AGENTS.md 第46行："第 3 次仍为'需修改'时，自动标记为'拒绝'"

**影响**：
- 两个部门对同一规则理解不一致
- 可能导致流程卡住

**优化建议**：
```
统一为：最多3轮，第3轮必须给出明确结论
- 第1轮：批准 / 需修改（附具体建议）
- 第2轮：批准 / 需修改（附具体建议）
- 第3轮：批准 / 拒绝（二选一，不能再"需修改"）

修改位置：
1. review_dept/SOUL.md 第114行
2. review_dept/AGENTS.md 第46行
3. planning_dept/SOUL.md 第192行
```

### 问题 4：异常处理机制不完整

**现状**：
- 断路器定义：超时30分钟、3次循环
- 但缺少"部分成功"的处理策略

**影响**：
- 当执行到一半失败时，用户不知道已完成什么
- 无法在中间点恢复任务

**优化建议**：
```
新增"检查点"机制
1. 每个部门完成子任务后，立即上报
2. 记录"已完成步骤"和"待完成步骤"
3. 失败时可从检查点恢复

检查点格式（存入 MEMORY.md）：
```
## 任务 JJC-xxx 检查点
- 完成：步骤1、步骤2
- 当前：步骤3（执行中）
- 待办：步骤4、步骤5
- 阻塞：[如果有]
```
```

### 问题 5：Token 消耗预估不准确

**现状**：
- 流程卡中有"Token预估"字段
- 但没有部门实际执行时的消耗记录

**影响**：
- 用户无法提前知道成本
- 可能超出预算

**优化建议**：
```
方案A：历史数据估算
- 在 MEMORY.md 中记录每类任务的平均 Token 消耗
- 流程卡生成时参考历史数据

方案B：实时监控
- 执行过程中记录实际 Token 消耗
- 接近预算时提醒用户

推荐：方案A
- 在 dispatch_center/MEMORY.md 中增加"任务成本库"
```

### 问题 6：用户反馈回路不够清晰

**现状**：
- 阶段性进展通知是"飞书简要通知"
- 但没有明确的"用户确认"机制

**影响**：
- 用户不知道何时需要介入
- 可能错过关键决策点

**优化建议**：
```
新增"决策点"通知
在关键节点主动询问用户：
1. 规划部完成初步方案后 → "方案A vs 方案B，您选择哪个？"
2. 执行中遇到备选方案时 → "遇到两种实现方式，您倾向哪种？"
3. 完成后 → "结果已产出，是否需要调整方向？"

通知格式：
```
┌─────────────────────────────────────┐
│ 🤔 需要您决定：[问题简述]            │
│ 选项：                              │
│   A. [选项A]                        │
│   B. [选项B]                        │
│ 请回复：A / B / 其他                 │
└─────────────────────────────────────┘
```
```
