# Edict 系统全面逻辑验证 - Product Requirement Document

## Overview
- **Summary**: 对 Edict 多部门协作系统进行全面的逻辑验证，包括规则解析、条件判断、执行流程和结果输出等核心功能模块，设计多组测试用例覆盖各种场景，确保系统在各种情况下均能正确执行。
- **Purpose**: 确保 Edict 系统的逻辑正确性、稳定性和可靠性，通过系统的测试发现潜在问题并提供修复建议。
- **Target Users**: 系统管理员、技术支持人员、系统维护者

## Goals
- 验证 Edict 系统所有核心功能模块的逻辑正确性
- 设计并执行全面的测试用例，覆盖正常场景、边界条件和异常情况
- 生成详细的测试报告，包含测试用例、执行结果、发现的问题及修复建议
- 确保系统在各种输入条件下的稳定性和可靠性

## Non-Goals (Out of Scope)
- 本项目不包含对系统性能优化的测试
- 本项目不包含对第三方集成的测试
- 本项目不包含对 UI/UX 的测试
- 本项目不包含对安全漏洞的深度渗透测试

## Background & Context
Edict 是一个现代化的多部门协作系统，由 12 个 AI Agent 组成：总调度中心分拣、规划部规划、审核部审核驳回、执行部派发、七部+人力资源部并行执行。系统的核心功能包括：
- 任务创建和管理
- 消息分拣和分发
- 状态流转和更新
- 看板更新和监控
- 子任务管理
- 进度汇报
- 任务取消、暂停和恢复

系统使用 Python 实现，基于 JSON 文件进行数据存储，提供 React 前端看板。

## Functional Requirements
- **FR-1**: 验证任务创建功能，包括任务ID生成、标题验证、状态设置等
- **FR-2**: 验证消息分拣逻辑，包括闲聊判断、指令识别、任务创建触发条件等
- **FR-3**: 验证状态流转功能，包括状态变更规则、流转记录更新、回调触发等
- **FR-4**: 验证条件判断逻辑，包括标题长度验证、标题内容清洗、组织映射等
- **FR-5**: 验证子任务管理功能，包括子任务创建、状态更新、进度跟踪等
- **FR-6**: 验证进度汇报功能，包括实时状态更新、计划清单管理、历史记录等
- **FR-7**: 验证任务取消、暂停和恢复功能，包括状态回滚、流转记录等
- **FR-8**: 验证文件锁机制，确保并发操作的数据一致性
- **FR-9**: 验证看板更新功能，包括任务源同步、实时数据刷新等
- **FR-10**: 验证错误处理和异常情况处理，确保系统在异常输入下仍能稳定运行

## Non-Functional Requirements
- **NFR-1**: 所有测试用例应在合理时间内执行完成（单测试用例 < 10秒）
- **NFR-2**: 测试报告应清晰、详细、易于理解
- **NFR-3**: 测试用例应具有可重复性，每次运行应得到一致结果
- **NFR-4**: 测试覆盖率应达到核心功能模块的 90% 以上

## Constraints
- **Technical**: 测试需在现有 Edict 系统上进行，不修改核心业务逻辑
- **Business**: 测试过程不应影响现有系统的正常运行
- **Dependencies**: 依赖 Edict 核心脚本、测试框架（pytest）、数据文件

## Assumptions
- 假设 Edict 系统已正确安装并配置
- 假设测试环境与生产环境一致
- 假设可以访问必要的数据文件和配置文件
- 假设可以使用临时目录进行测试数据的隔离

## Acceptance Criteria

### AC-1: 任务创建功能验证
- **Given**: 系统已正确安装并配置，测试数据目录已准备
- **When**: 调用任务创建功能，传入有效和无效的参数
- **Then**: 有效参数应成功创建任务，无效参数应被正确拒绝
- **Verification**: `programmatic`
- **Notes**: 测试边界条件如空标题、过长标题、特殊字符标题等

### AC-2: 消息分拣逻辑验证
- **Given**: 系统已正确配置，包含各种类型的测试消息
- **When**: 传入各种类型的消息（闲聊、问答、指令等）
- **Then**: 系统应正确判断消息类型并采取相应行动
- **Verification**: `programmatic`
- **Notes**: 测试边界条件如刚好 10 字的消息、前缀判断等

### AC-3: 状态流转功能验证
- **Given**: 存在处于不同状态的任务
- **When**: 触发状态流转操作
- **Then**: 状态应正确变更，流转记录应被正确记录
- **Verification**: `programmatic`
- **Notes**: 测试所有可能的状态转换路径

### AC-4: 条件判断逻辑验证
- **Given**: 测试各种条件判断场景
- **When**: 传入需要进行条件判断的输入
- **Then**: 系统应返回正确的判断结果
- **Verification**: `programmatic`
- **Notes**: 测试边界条件如特殊字符、超长文本等

### AC-5: 子任务管理功能验证
- **Given**: 存在具有子任务的任务
- **When**: 对子任务进行操作（创建、更新、删除）
- **Then**: 子任务操作应正确执行并反映在父任务上
- **Verification**: `programmatic`
- **Notes**: 测试子任务的各种状态转换

### AC-6: 进度汇报功能验证
- **Given**: 存在正在进行的任务
- **When**: 调用进度汇报功能
- **Then**: 进度信息应被正确更新和记录
- **Verification**: `programmatic`
- **Notes**: 测试进度更新频率、计划清单管理等

### AC-7: 任务取消/暂停/恢复功能验证
- **Given**: 存在活跃任务
- **When**: 执行取消、暂停或恢复操作
- **Then**: 操作应正确执行，状态应正确回滚或前进
- **Verification**: `programmatic`
- **Notes**: 测试各种状态下的取消/暂停/恢复操作

### AC-8: 文件锁机制验证
- **Given**: 多个并发操作尝试同时访问同一文件
- **When**: 执行并发写入操作
- **Then**: 文件锁机制应保证数据一致性，不应出现数据损坏
- **Verification**: `programmatic`
- **Notes**: 使用多线程/多进程测试并发场景

### AC-9: 看板更新功能验证
- **Given**: 任务状态发生变更
- **When**: 触发看板更新
- **Then**: 看板数据应被正确同步和刷新
- **Verification**: `programmatic`
- **Notes**: 测试数据刷新的正确性和及时性

### AC-10: 错误处理和异常情况处理验证
- **Given**: 传入异常输入或触发异常条件
- **When**: 系统尝试处理异常
- **Then**: 系统应能优雅地处理异常，提供有意义的错误信息，不应崩溃
- **Verification**: `programmatic`
- **Notes**: 测试各种异常场景如文件不存在、权限问题、格式错误等

### AC-11: 测试报告生成
- **Given**: 所有测试用例已执行完成
- **When**: 生成测试报告
- **Then**: 测试报告应包含所有测试用例、执行结果、发现的问题及修复建议
- **Verification**: `human-judgment`
- **Notes**: 报告格式应规范、内容应完整
